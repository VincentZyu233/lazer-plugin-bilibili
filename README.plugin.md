# 哔哩哔哩（Lazer Lua 插件）

把 B 站当作曲库：搜索、播放、歌词、收藏夹、排行榜、热门、相关推荐、UP 主投稿、评论、多分 P、扫码 / Cookie 登录。

运行于 Lazer 的 Lua 插件宿主（v2.0.210 实测，仅使用该版本提供的 14 个 host API）。

## 安装

1. 下载 `community.bilibili.music.zip`（不要解压改目录结构，ZIP 根目录必须是 `manifest.json`）。
2. Lazer → 插件管理 → 导入 ZIP 插件 → 选择该 ZIP。
3. 列表出现「哔哩哔哩」并处于启用状态即可；首次联网会请求网络授权，需要允许。

## 登录

两种方式，任选其一：

- **扫码**（推荐）：插件登录框点扫码 → 用哔哩哔哩 App 扫二维码 → 在 App 中确认。扫码成功后自动下发并保存登录态，无需手动复制 Cookie。
- **Cookie**（兜底）：浏览器登录 `www.bilibili.com`，从开发者工具复制完整 Cookie（必须含 `SESSDATA` 与 `bili_jct`），粘贴到插件的 Cookie 登录框。缺 `bili_jct` 时收藏类写操作必然失败，因此缺任一项会被直接拒绝、不发请求。

> 扫码若提示「不支持的二维码」：`qrcode_key` 有时效，先**重新打开登录页生成新码**，不要复用旧码；反复失败再用 Cookie 登录兜底。

## 能力

- 搜索（WBI 签名，秒级 `wts`）、单曲详情、音频流（自动选最高音质，可指定 `original`/`flac`）
- 歌词（B 站站内字幕为主源，语言优先级 人工中文 > `ai-zh` > 其他 `ai-*`；返回逐行时间轴由宿主合成；lrclib 仅作兜底）
- 首页热门、全站排行（id 形如 `chart:0`）、相关推荐、UP 主投稿、评论（最新 / 热门双桶）
- **多分 P**：`homeFeed.albums` / `albums` 暴露多 P 视频，`albumSongs` 列出各 P，曲目身份为 `bvid:cid`
- 登录后：本人收藏夹、默认收藏夹喜欢列表、加/取消喜欢、添加到歌单、新建歌单

## 曲目身份（`bvid` 与 `bvid:cid`）

曲目 id 可能是 `BV1xx411c7mD`（整个视频）或 `BV1xx411c7mD:43727326650`（精确到某一 P）。

- 所有 op 收到 song id 都先解析，再从结果里取需要的部分：需要"整个视频"的接口（`view`/`playurl`/`reply`/`fav`）只用 `bvid`，需要"精确到 P"的接口（`stream`/`lyrics`/`song`）用 `bvid + cid`。
- 纯 `bvid` 的行为与旧版逐字节一致，宿主已有的歌词与播放缓存仍然命中。
- 榜单与首页热门自带 `cid`，所以这两块的 id 带冒号；搜索、相关推荐、收藏夹的行在真站响应里没有 `cid`，所以是纯 `bvid`。

## 分页语义

宿主用**返回行数**判定"还有没有下一页"，所以插件必须每次都返回 `min(limit, 剩余)` 行。

- 收藏夹远端页可能短于请求的 `ps`（失效稿件在服务端被过滤），页边界只按已取到页的实际长度累计定位。
- 越界页只证明"到头了"，不证明"有多少"：`/x/v3/fav/resource/list` 在 `pn` 超过末页时同时返回空数组与 `media_count: 0`。游标里的 `total` 只在非空页写入，另设 `proven`（真实读到的行数下界），两者分开维护。
- 评论页是严格位置切片，深 offset 直接跳页；收藏夹不能跳页，只能顺序走。
- 请求预算按族分开：签名族（WBI 请求）12 次，明文族 32 次。预算耗尽又没凑满 `limit` 时报可重试错误，**不返回短页**——短页等于把"读不到"伪装成"没有了"。
- 评论分两个桶：`latest` 走时间序、可翻页；`hot` 只在第一页请求一次，失败留空且不缓存，不参与分页与 `total`。
- 专辑架候选集为「热门 + 榜单原始行」，按 bvid 去重、热门优先，共用一个 6 h 缓存。榜单失败时只丢榜单候选，且降级结果不写缓存。

## 已知限制

- 只取音频流（`m4s` / FLAC），不含视频画面；音质通过 `quality` 参数选择，不提供设置页（v2.0.210 无该扩展点）。
- `search` 单次最多返回 35 行，超过会被夹到 35 并标 `truncated`。宿主按返回行数判末页，所以 `limit > 35` 的调用方会被告知"没有更多"——这是指令预算所迫的取舍。
- 歌词取 B 站视频自带的字幕（与视频同源、时间轴零误差），需要登录态；无字幕时才去 lrclib 按标题与艺术家匹配。8 小时以上的合集只取前 1200 行。
- **纯音乐会显示"重试"**：插件从不返回空歌词表。v2.0.210 会把空答复落成不带时间戳的 `pureMusic` 空壳且无法过期，所以"两个源都没有"一律报可重试错误，而不是"纯音乐"。
- UP 主页投稿接口受平台限制时可能为空列表，此时名字与头像仍正常显示。
- 不实现楼中楼、评论点赞与位置式 `removeFromPlaylist`（宿主传列表位置、B 站要 `aid`，映射错了会删错歌）。
- 高频访问可能触发 B 站风控（`-412`）；归为限流并**不自动重试**（插件无 sleep 能力，立即重试只会加重封禁）。
- 搜索页仍是 4 个 tab，其中专辑 / 歌单为空——B 站没有对应的「专辑」层，收成 2 tab 需要改宿主 UI。

## 隐私

Cookie / SESSDATA 仅保存在本插件的 `lua_plugin_data` 存储沙箱，用于维持登录态；不会随错误信息外泄——所有操作失败只返回状态码，不含响应正文、Cookie 或签名 URL。

设备标识（`buvid3`/`buvid4`）同样只存在该沙箱里：它是风控需要的稳定设备态，不是凭据。

重定向信任边界：同主机 30x 才吸收 `Set-Cookie`（合并基数是本次请求实际携带的 cookie），跨主机 30x 一行都不吸收且后续响应也不再吸收；最多 3 跳。
