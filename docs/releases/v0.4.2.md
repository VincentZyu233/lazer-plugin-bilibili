# v0.4.2 — 功能稳定版

从最初设计到 v0.4.2，插件完成了从「接口能调通」到「功能在宿主里真正可达、可翻页、可恢复、可验证」的转变。当前没有阻塞发布的功能缺陷，本版作为这一阶段的功能稳定版。

### 本版新增

1. **首页专辑架从 0 变为 5**
   - 候选集改为「热门 + 榜单**原始行**」，按 bvid 去重、热门优先。
   - 真机冷启动 8 请求 / 1 599 ms → `songs=20 albums=5`；热缓存零新增请求。

2. **首页与 `albums()` 共用一份缓存**
   - 两个入口同源后分缓存只会把同一份列表请求两遍。缓存键收成单个 `wide`。

3. **榜单失败窄降级**
   - 只对榜单这一条请求做 `pcall`，热门失败照常上抛（它是首页主内容）。
   - 降级结果**不写** 6 小时缓存，一次临时故障不会被钉住；`albums()` 是显式浏览操作，榜单失败照旧上抛。

4. **view 按尝试次数限流**
   - `view ≤ 16` 数的是实际发出的请求数，不是成功数。旧代码数成功数，一次 `view` 失败就让实际支出越过 16 而断言仍绿。

### 修复

- 旧版 `chart_rows` 把 100 行映射成 song 形状后再读专辑：映射后没有 `videos` 字段，且预算按解码行数计，真机直接 `408`。改读原始行后 6 请求正常返回。
- `if #out >= ALBUM_LIMIT` 数成功数的问题（见上）。

### 用户可见的改变

**登录与账号**：扫码登录从二维码无法识别修到自动接收并保存完整登录态；`qrUrl` 返回纯 URL；Cookie 登录校验 `SESSDATA` 与 `bili_jct`；buvid 持久化；存储清理不再误删登录态；写操作不自动重放。

**搜索与分页**：搜索分成视频和 UP 主两个桶；分页从「请求一页、短页即结束」升级为远端聚合 + 本地切片 + 按实际页长定位 + 深偏移跳页 + 重复页检测 + 游标总数与已证明行数分离；搜索在真实指令预算下稳定返回最多 35 行。

**多分 P**：`首页/榜单发现多 P → album 表示视频容器 → albumSongs 列出各 P → bvid:cid 精确标识每一 P → song/stream/lyrics 使用对应 cid`。同时修复了 P2 播放成 P1、P2 歌词读 P1、合集只显示前 30 P、空 cid 导致页长缩短与 offset 错位。

**首页与排行榜**：排行榜从错误的 `rank:all` 改为可消费的 `chart:<rid>`；首页专辑候选从「只读热门」改为「热门 + 榜单原始行」；榜单失败只牺牲榜单候选。

**评论**：正文从 `content.message` 正确提取；`bvid:cid` 不再被错误编码进 `view?bvid=`；深评论窗口使用严格位置跳页；最新评论 `sort=0`，热门评论 `sort=1` 只在第一页请求一次；非空页缺 count 时不再把评论区永久锁在第一页。

**歌词**：B 站字幕为主源、LRCLIB 为兜底；返回结构化 `lines[]`；支持人工中文 > `ai-zh` > 其他 `ai-*` 的优先级；无结果和暂时失败不再统一伪装成纯音乐；保留 1200 行指令预算保护。

**收藏与歌单**：收藏夹补齐 `writable`、`owner`；默认收藏夹与「我喜欢」正常联动；支持新建收藏夹和向指定收藏夹添加歌曲；收藏夹封面采用预算化回填与缓存；`removeFromPlaylist` 仍明确不实现（宿主传位置、B 站要 aid）。

### 工程与测试

测试从约 20 条增长到 **134 条**，但更重要的是覆盖了真实行为：

- 每个测试使用独立 VM 和独立存储，消除状态串联；
- fixture 使用真站字段和真实末端行为；
- 新缺陷先在旧代码上复现红，再验证修复转绿；
- 直接模拟宿主 `hasMore`、`nextOffset` 和 `all()`；
- 增加负向控制，证明 `chart_raw`、页长契约等确实承重；
- ZIP、源码、安装目录进行逐字节校验。

### 宿主兼容性

- 实测宿主：Lazer v2.0.210（Windows x64），仅使用该版本提供的 14 个 host API。
- 纯 Lua，无原生依赖；ZIP 15 个文件，约 51 KB。

### 已知边界

以下属于已知限制，不是本轮遗漏：

- `search` 单次最多 35 行；`limit > 35` 时宿主会判定末页。
- 只提供音频，不提供视频画面。
- 超长字幕最多取前 1200 行。
- 纯音乐在旧宿主上可能显示可重试，而不是稳定的「纯音乐」状态。
- UP 投稿接口受平台限制时仍可能为空。
- 不实现楼中楼、评论点赞和位置式 `removeFromPlaylist`。
- 搜索 tab、401 文案和宿主歌词缓存策略仍需宿主侧修改。

### 验证

- 契约测试 **134/134**；静态门 11 项全 0。
- 真机：首页 20 首歌曲、5 个多 P 专辑；冷启动 8 请求，热缓存零新增请求。
- 安装：15/15 文件逐字节一致，`.network-enabled` 在位。
